## 0. Foundations

### 0.1 The product in ten lines
- **Carousel Studio («كاروسيل ستوديو»)**: a free, open-source (Apache-2.0) Claude plugin that plans, writes and designs Instagram carousels and single posts, Arabic first (Egyptian, Gulf, Levantine, white MSA) plus English. Author: Mohamed Abdou (محمد عبده).
- **Seven skills** (`carousel-create`, `content-angles`, `brand-setup`, `arabic-proofread`, `carousel-design`, `content-plan`, `visual-prompts`), **six commands** (`/carousel /post /brand /plan /audit /studio`), **nine agents**, the creative team (`cs-creative-director`, `cs-strategist`, `cs-copywriter`, `cs-arabic-editor`, `cs-art-director`, `cs-motion-designer`, `cs-visual-artist`, `cs-audience-panel`, `cs-qa-producer`), generated by `tools/sync_team.py` from `team/`.
- **The Studio** is a self-contained HTML artifact that runs in the user's browser (web, desktop, phone). It renders every slide from `spec.json`, lets the user edit text in place, restyle, regenerate a slide, check quality gates and export PNG / MP4 / PDF / ZIP. Nothing is exported through Claude's servers.
- **The same DOM** is the source for the editor, the PNG/JPEG painters, the animated cover and Claude Code's headless render. One layout engine, one set of rules.
- **Canvas** 1080×1440 (3:4) with a centred 1012×1350 safe box; auto-crop to 4:5 (1080×1350) for APIs and schedulers.
- **Deliverable per post:** slide 1 as a looping MP4 cover (6 s, poster-first), other slides as PNG, caption, per-slide captions, ≤5 hashtags, Arabic alt text per slide, PDF, QA report; the editable source files (`spec.json`, `cover.hf.html`, `studio-source.html`, together over 10 MB) are an opt-in export, so the default kit stays light enough to move to a phone (≤ 4 MB for 8 slides).
- **Hard limits (Q39/Q40):** 8–12 slides (warn under 6); cover hero ≤6 words, cover total ≤12; body ≤25 words (hard cap 35); ≤5 hashtags; caption 300–900 characters by default.
- **Digits:** Western 0–9 by default; Arabic-Indic ٠–٩ is an opt-in. One digit system per design.
- **AI never writes Arabic inside images.** External image/video tools are optional and only supply text-free plates.
- **Credits** («من صنع محمد عبده» and his socials) appear only in tool screens (Studio About, Brand Home, onboarding welcome, README). Nothing exported carries his name. Users own everything they create.

### 0.2 Hard rules (apply to every package)
1. Write **only the files your package owns** (section 2). Code against the contract for everything else; list assumptions in your summary.
2. Directory rules: no top-level `bin/`; every non-image, non-font file **< 256 KiB**; runtime JS chunks **≤ 200 KiB** each; UTF-8 (no BOM), LF newlines; valid JSON; plugin ≤ 480 files (CI fails at 480, directory limit 512).
3. Skills are **self-contained**: nothing under `skills/<name>/` may read a path outside that skill folder at runtime. Shared files reach other skills as synced copies (section 2.4).
4. Python: **3.11 standard library only**, runs on Windows and Linux. Always `open(..., encoding="utf-8")`, use `pathlib`, no shell-specific calls, no `os.system`. Node (`.mjs`) only for the Claude Code lane and repo tooling.
5. **No GSAP, no Remotion, no telemetry or analytics code, no network calls from skills** unless the user asks. The browser runtime may load only `mediabunny@1.61.0` and `fflate@0.8.2`, from `https://cdn.jsdelivr.net/npm/` at exactly those versions.
7. Arabic rules (enforced by the engine and checked by QA): `dir="rtl" lang="ar"`; never letter-spacing, justification, italic/slant or font-synthesis on Arabic; no `opacity`/RGBA on Arabic text nodes (group opacity on whole words or lines only, in motion); isolate every LTR run (English, numbers with units, @handles, #tags, URLs, phones) with `<bdi dir="ltr">`; one digit system per design; Arabic punctuation ، ؛ ؟; kashida on at most one headline word and only where the preset allows; AI never writes Arabic inside images.
8. Quality bar: public product, design-sensitive owner. Professional, consistent, well-organised code and docs. No placeholder motion, no lorem ipsum, no "TODO" strings in shipped user-facing text.
9. Nothing in `plugins/carousel-studio/` may mention the owner's name except the files listed in 0.6.

### 0.3 Glossary
| Term | Meaning |
|---|---|
| **spec** | `spec.json`, one post (carousel or single). The Studio's only input. Schema: `schemas/spec.schema.json`. |
| **brand** | `brand.json`, one per brand (creator, business or client). |
| **preset** | A look: tokens + `decor.css` + variant flags. Six in v1: `swiss creator notebook poster interface heritage`. |
| **archetype** | A slide-type layout partial (20 types). Archetypes own layout; presets own look. |
| **architecture** | The structure of a whole carousel (listicle, steps, myth-fact …). Not the same as archetype. |
| **slot** | A named field region inside an archetype (`data-slot`). |
| **slide id** | `s01`…`s20`, stable identity of a slide; `n` is its current position. |
| **token** | One resolved style value (colour, font, size …) with a dotted path such as `roles.accent`. |
| **resolve** | `preset ← brand ← occasion ← post overrides ← slide overrides → floors` (section 6.4). |
| **fit** | Search for the largest font size at which a slot fits (section 4.3). |
| **freeze** | Store line breaks and `tokensHash` at approval so exports are deterministic. |
| **painter** | Code that turns a slide DOM into pixels: `svg` (foreignObject → canvas) or `replay` (redraw from measured rects). |
| **poster** | The finished slide-1 design. In a motion timeline, frame 0 = poster = last frame. |
| **plate** | A text-free generated background image or video. |
| **gate** | One QA check family with an id (`C1`, `D4` …). |
| **kit** | The publishing kit ZIP («حزمة النشر»). |
| **lane** | `studio` (user's browser), `sandbox` (Claude app Python only), `claude-code` (local Node + Playwright + HyperFrames). |
| **checkpoint** | `angle` → `script` → `design` → `ready` → `exported`. |
| **Brand Home** | The long-lived per-brand artifact (Brand Book, Plan, Ideas, Posts). |

### 0.4 Conventions
**Naming.** JSON keys are `camelCase`. Enumerated *values* are `kebab-case` lowercase, with these fixed exceptions: gate ids (`C1`, `SRC1`), severities (`BLOCK FIX NOTE`), hook family codes (`P1 F17 S3`), evidence tags (`D-own D O EC SE`), dialect code `msa-white`, ISO country codes, dotted capability ids (`image.generate`). Files: `kebab-case`; Python modules `snake_case`; JS source files `kebab-case.js`.

**Encoding and time.** UTF-8 without BOM, LF line endings. Timestamps are ISO-8601 UTC with `Z`. Durations in seconds (float). Lengths in CSS px at the 1080-wide canvas unless a name says otherwise. Fractions are 0–1.

**Identifiers.** Patterns are in the schemas (`id`, `shortId`, `slug`, `presetSlug`). Slide ids `s01…s20` are never reused after deletion within a spec.

**Versions and pins.**
| Constant | Value |
|---|---|
| `CONTRACT_VERSION` | `1.0` |
| `ENGINE` (`CS.version`, `frozen.engine`, `qa.engine`) | `cs-1.1.0` |
| `specVersion`, every `schemaVersion` | `1` |
| `PLUGIN_VERSION` | `1.1.0` |
| `MEDIABUNNY` | `1.61.0` → `https://cdn.jsdelivr.net/npm/mediabunny@1.61.0/+esm` |
| `FFLATE` | `0.8.2` → `https://cdn.jsdelivr.net/npm/fflate@0.8.2/umd/index.js` |
| `HYPERFRAMES_VERSION` (Claude Code lane CLI) | `0.8.185` (latest on npm on 2026-10-22; B3 smoke-renders it and, only if it fails, moves to the nearest version that passes and records the date in a comment) |

**Errors.** Browser code throws `CSError` (`class CSError extends Error { code: string; detail?: any }`). Codes: `E_SCHEMA`, `E_FONT_MISSING`, `E_FIT_OVERFLOW`, `E_PAINT_TAINTED`, `E_PAINT_UNSUPPORTED`, `E_ENCODER_UNSUPPORTED`, `E_DEP_LOAD`, `E_NO_CAPABILITY`, `E_CONFLICT`, `E_ABORTED`, `E_USAGE`. Python raises `_cs.CSError` (same codes). CLI scripts print errors to **stderr** as `cs-error: <code>: <message>` and exit with a code from the table below. JSON output (`--format json`) always goes to **stdout** and is a single object or array.

**Exit codes (all CLIs).**
| Code | Meaning |
|---|---|

| 1 | finished, FIX-level findings pending |
| 2 | finished, BLOCK-level findings, or input invalid against its schema |

| 65 | data format error (unparseable JSON / HTML) |
| 66 | input file missing |
| 70 | internal error |
| 73 | cannot write output |
| 75 | conflict (`rev` mismatch) |

## 2. File-ownership map

### 2.1 Rules
1. **One owner per path.** The owner is the only package that creates or edits it. Paths marked **SYNC** are written only by `tools/sync_shared.py` (B1) from their canonical source. Paths marked **GEN** are written only by `tools/build.mjs` (B1).
2. **Do not touch** a path you do not own, even to fix a typo. Put the fix in your summary.
3. **Tests.** A package owns the tests of the code it owns: JS in `tests/unit/js/<module>/`, Python in `tests/unit/py/test_<script-or-module>.py`. Cross-cutting corpora belong to B12 (table below).
4. **Private builds.** During the sprint a module owner may run `node tools/build.mjs --module <name> --out <private dir>` to test; only the integration step (B1, after all packages report) writes `runtime/`.
5. **Order of work.** Everything can start at once because every interface is in this file. Stubs for another package's API are allowed **inside your own tests only**.

## 3. Cross-cutting specifications

Everything in this section is implemented **twice** (JavaScript in `src/lib/`, Python in `scripts/_cs/`, both by B4) and must give **identical results** on the shared conformance corpus (`tests/conformance/corpus/`, B12). B2 and the skill builders rely on it.

### 3.1 JSON Schema subset (the validator both languages implement)
Schemas are JSON Schema 2020-12 restricted to these keywords; any other keyword (except annotations `title description examples default $comment $schema $id x-*`) makes the schema invalid.

`type` (string or array of: `string integer number boolean object array null`), `enum`, `const`, `properties`, `required`, `additionalProperties` (boolean or schema; **default allowed**), `minProperties`, `items` (one schema), `minItems`, `maxItems`, `uniqueItems`, `minLength`, `maxLength`, `pattern`, `minimum`, `maximum`, `oneOf`, `anyOf`, `allOf`, `$ref` (local `#/$defs/<name>` only), `$defs`. `format` is an annotation and is **not** enforced.

Rules:
- `integer` accepts any number with an integral value (`3` and `3.0`); `boolean` is never a number.
- Lengths count Unicode code points (not UTF-16 units, not bytes).
- Regex portability: patterns use only `^ $ . [] {} () | * + ?`, the escapes `\.` `\+` `\/` `\-` `\|` `\t` `\n` `\r` `\uXXXX` and explicit ranges. **Never `\d \w \s \b`, lookbehind or named groups** (Python's `\d` matches Arabic-Indic digits, JavaScript's does not). Digits are `[0-9]`. `$` means end of string only (Python implementations translate it to `\Z`; a trailing newline must not match). Patterns are matched unanchored with `search` semantics, so schemas anchor them with `^…$`.
- A validation error is `{ "path": "/slides/2/title", "keyword": "maxLength", "message": "…" }` (`path` = JSON Pointer, `""` for the root). Errors are sorted by `path`, then `keyword`. A `oneOf` failure yields one error at the `oneOf` path.
- `$ref` resolves against the root of the schema file. A caller may validate against a sub-definition (`def` argument), e.g. `hook-library` = `hook.schema.json#/$defs/library`.
- Each schema has `x-sharedDefs`: names of `$defs` that are byte-identical copies across schemas. `tests/unit/py/test_schema_defs.py` (B4) fails if two schemas disagree.

### 3.2 Canonical JSON and hashes
`canonicalJSON(value)`:
1. Objects: keys sorted ascending by Unicode code point (all hashed keys are ASCII). No whitespace anywhere.
2. Strings: first normalised to **NFC**; escaped minimally — only `"`, `\`, and U+0000–U+001F (`\b \t \n \f \r`, others `\u00xx` lowercase hex). Every other character is written literally.
3. Numbers: integers in decimal; other numbers as the shortest round-trip form (`String(n)` in JS, `repr(float)` in Python); integral floats print as integers; `-0` prints `0`; `NaN`, `Infinity` and magnitudes ≥ 1e21 or in (0, 1e-6) are errors.
4. `null`, `true`, `false` literal. `undefined` members are omitted.

`hash16(value)` = **FNV-1a 64-bit** of the UTF-8 bytes of `canonicalJSON(value)` (offset basis `0xcbf29ce484222325`, prime `0x100000001b3`), printed as 16 lowercase hex digits. API: `CS.core.canon.hash(value)` / `_cs.canon.hash16(value)`. Hashes detect change; they are not security features.

What is hashed:
| Field | Input |
|---|---|
| `spec.brand.snapshotHash` | `brandSnapshot(brand)` = the brand object **without** `updatedAt createdAt ext onboarding hooks.history visual.logo.dataUri` |
| `spec.style.resolvedHash` | `tokensHash` of the post-level resolved tokens (3.2.1) |
| `spec.frozen.tokensHash` | `{post: hashable(postTokens), slides: [[slideId, variant or null, hash16(overrides or {})] …]}` hashed with `hash16` |

3.2.1 `hashable(tokens)` = the `ResolvedTokens` object without `provenance`, `adjustments`, `css`, `hash`.

### 3.3 Text model (single definition for `CS.core.text` and `_cs.text`)
**Normalisation.** Stored copy is NFC. Never strip U+200C/U+200D. The tool never inserts U+200E/U+200F into stored copy.

**Markup in text fields.** Only two constructs: `==span==` marks the emphasis span (not nested, not across a newline, at most one per text field; an unmatched `==` is literal) and `\n` is a forced line break. Everything else is literal text and is HTML-escaped on render. `parseMarkup(s) → {plain, spans:[{start,end}], breaks:[index]}`; `stripMarkup(s) → plain` (newline becomes a space).

**Whitespace (WS).** The explicit class `[ \t\n\r\f\v\u00A0\u202F]`. Implementations must not use their engine's `\s`; wherever `\s` appears in a pattern of this section it means exactly WS.

**Words.** After `stripMarkup`, split on `WS+`. A token is *countable* if it contains at least one Unicode letter or number (category `L*` or `N*`). Pure punctuation, `…`, `...`, `—`, emoji-only tokens are not counted. `wordCount(s)` = number of countable tokens. A clitic-prefixed Arabic word (وبالمنتج) is one word; `لـChatGPT` (no space) is one word; `5 ساعات` is two. `charCount(s)` = code points of NFC text.

**Tokenizer.** `tokenize(s) → Token[]`, `Token = {kind, text, start, end, ltr}` (`start/end` are code-point offsets). It scans left to right and takes the first pattern that matches at the current position, in this order:

| # | kind | Pattern (portable regex) | `ltr` |
|---|---|---|---|
| 1 | `url` | `https?://[^\s<>"]+` · `www\.[^\s<>"]+` · `[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)*\.[a-z]{2,24}(/[^\s<>"]*)?` (domain form only if the last label has letters only) | yes |
| 2 | `email` | `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` | yes |
| 3 | `handle` | `@[A-Za-z0-9._]{1,30}` | yes |
| 4 | `tag` | `#[^\s#<>]+` (direction: `ltr` if the tag has no Arabic letter, else `rtl`) | by content |
| 5 | `phone` | `\+?[0-9][0-9\u00A0 ()-]{7,}[0-9]` | yes |
| 6 | `number` | `[$€£]?[0-9]+([.,][0-9]+)*(%\|[A-Za-z]{1,6})?` (Western) · `[\u0660-\u0669]+([\u066B\u066C][\u0660-\u0669]+)*\u066A?` (Arabic-Indic) · `[\u06F0-\u06F9]+` (Persian, always a violation) | Western yes; Arabic-Indic no |
| 7 | `latin` | `[A-Za-z\u00C0-\u024F][A-Za-z0-9\u00C0-\u024F'\u2019._\-+/&]*` then trailing `. - _ / & '` trimmed | yes |
| 8 | `emoji` | `[\u2600-\u27BF\u2B50\u2B55\U0001F000-\U0001FAFF][\uFE0F\u200D\u2600-\u27BF\U0001F000-\U0001FAFF]*` | no |
| 9 | `ar` | `[\u0621-\u064A\u064B-\u0652\u0640\u066E-\u06D3\u06D5\u06FA-\u06FF\u0750-\u077F\u08A0-\u08FF\uFB50-\uFDFF\uFE70-\uFEFF]+` | no |
| 10 | `space` | `[ \t\n\r\f\v\u00A0\u202F]+` | – |
| 11 | `punct` | any single remaining character | – |

Astral code points are written `\U0001F000` above; JavaScript uses `\u{1F000}` with the `u` flag, Python `\U0001F000`. Tokens never overlap; `start/end` are code-point offsets.

**LTR isolation and binding (what `toHTML` produces).**
1. Consecutive `ltr` tokens (`latin number handle url email phone tag-ltr`) separated by exactly one ordinary space merge into **one run**. Each run is emitted as `<bdi dir="ltr" class="cs-ltr" data-run="latin|number|handle|tag|url|email|phone">…</bdi>`; Arabic-script tags as `<bdi dir="rtl" class="cs-rtl" data-run="tag">`. Emoji are wrapped in `<span class="cs-emoji">` without `bdi`.
2. An `ar` token that is immediately followed (no space) by an LTR run stays in the **same word unit**: `لـChatGPT` → one `.w`.
3. A `number` token followed by one ordinary space and an `ar` token, or an `ar` token from the list `copy.json → lists.bindLabels` (الخطوة، رقم، نصيحة، الجزء …) followed by a `number` token, gets that space replaced by **U+00A0** so the pair never splits across lines.
4. Every whitespace-separated word unit is wrapped `<span class="w" data-w="<index within the field>">…</span>`. A multi-word LTR run keeps its `.w` children inside the `bdi`.
5. Text is HTML-escaped. `==span==` becomes `<mark class="cs-em" data-m="em">…</mark>` wrapping whole `.w` units.

Emphasis always wraps whole word units; a `==` boundary that falls inside a word is extended to the whole word.

Example — input `==الذكاء== الاصطناعي في ChatGPT Plus بـ$20 شهريًا` renders (line-wrapped here only for reading) as:
```html
<mark class="cs-em" data-m="em"><span class="w" data-w="0">الذكاء</span></mark>
<span class="w" data-w="1">الاصطناعي</span> <span class="w" data-w="2">في</span>
<bdi dir="ltr" class="cs-ltr" data-run="latin"><span class="w" data-w="3">ChatGPT</span> <span class="w" data-w="4">Plus</span></bdi>
<span class="w" data-w="5">بـ<bdi dir="ltr" class="cs-ltr" data-run="number">$20</bdi></span> <span class="w" data-w="6">شهريًا</span>
```

**Digits.**
- `detectDigits(s)` → `"western" | "arabic-indic" | "persian" | "mixed" | "none"` looking only at digits outside `handle tag url email phone` tokens and outside any token that contains a Latin letter (`GPT4`, `4K`). `persian` = any U+06F0–06F9; `mixed` = more than one system.
- `convertDigits(s, to)` converts the digits of every `number` token (Western, Arabic-Indic and Persian → `to`) except inside the excluded tokens above. Decimal `.` between digits ↔ `٫` (U+066B); a comma followed by exactly three digits per group (`1,200`) ↔ `٬` (U+066C); `%` ↔ `٪` (U+066A). Nothing else changes.
- `formatNumber(value, digits)` formats a `number.value` string (Western, `.` decimal) for display.
- `counter(i, n, digits, lang)` → `"{i} من {n}"` (Arabic) or `"{i}/{n}"` (English) with digits converted; `remaining(k, digits, lang)` → `"باقي {k}"` / `"{k} left"`.

**Similarity.** `skeleton(s)`: NFC → lowercase Latin → delete U+064B–065F, U+0670, U+0640 → map `أ إ آ ٱ → ا`, `ى → ي`, `ة → ه`, `ؤ → و`, `ئ → ي` → convert all digits to Western → delete every character that is not a letter or number. `similarity(a, b)` = Dice coefficient over the sets of **character trigrams** of the two skeletons (a skeleton shorter than 3 code points is its own single gram); two empty skeletons give `1`, one empty gives `0`. Used by C7 (hook reuse ≥ 0.8) and C9 (caption first line vs cover < 0.6).

**Arabic helpers (JS only, `CS.core.text.arabic`).** `joiningType(cp) → "D"|"R"|"U"|"T"|"C"` (dual, right, non-joining, transparent, causing) from a built-in table for U+0621–U+064A, U+066E–U+06D3, U+0750–U+077F; `kashida.positions(word)` → indices after a dual-joining letter that is followed by a dual- or right-joining letter; `kashida.apply(word, count = 3)` inserts `count` × U+0640 at the single best position (preference: after س ش ص ض ب ن ي ت then the first eligible); returns the word unchanged if the word has fewer than 3 letters. `hasTashkeel(s)`; `hasArabic(s)`.

## 4. Browser runtime: `window.CS`

One global namespace, `window.CS`, with sub-modules **`CS.core`, `CS.qa`, `CS.paint`, `CS.motion`, `CS.export`, `CS.ui`** (plus `CS.motion.hf`, `CS.export.mp4`, `CS.ui.brandBook`). Signatures are TypeScript-style for precision only; the code is plain ES2020 JavaScript with JSDoc.

### 4.0 Build, loading, namespace
- **Source** lives in `src/<module>/*.js` as plain scripts (no `import`/`export`, no TypeScript, no JSX). Each module has `manifest.json` (`{"module","chunk","files":[…]}`).
- **Build** (`tools/build.mjs`, B1) concatenates the files of a module, in manifest order, into one chunk:

  ```
  /*! Carousel Studio runtime chunk <chunk> · cs-1.1.0 · Apache-2.0 */
  (function () {
    "use strict";
    var CS = (window.CS = window.CS || {});
    /* ---- file: <name>.js ---- */
    …file text…
  })();
  ```

  Files of one chunk share the IIFE scope. `src/lib` (`order` 0) + `src/core` (`order` 1) form `cs-core.js`. Output is not minified (readable, ≤ 200 KiB per chunk; the build fails above that).

### 4.2 `CS` root behaviour
- `window.__csReady` (boolean, initially `false`) becomes `true` after the first complete render **and** `document.fonts.ready` **and** two animation frames; at that moment `cs:ready` is emitted and `CS.automation.ready` resolves. `render.mjs` waits on it.
- `CS.automation` is created by `cs-export.js` (section 4.7) and is active only if `location.search` contains `automation=1` or `window.__CS_AUTOMATION === true`.
- All asynchronous functions accept an optional `signal: AbortSignal` in their options and reject with `CSError("E_ABORTED")`.

Fit algorithm (normative, B2): for each text slot (priority order hero → h1 → title → h2 → body → bullets → small/micro), set `font-size` inline in px and test sizes from the role's maximum down to `floorPx(role)` in 1 px steps (binary search allowed; result must equal the linear scan). `floorPx`: hero = `floors.hero` (96); body and bullets = `floors.body` (42); small, micro, kicker, bridge, attribution, labels = `floors.meta` (30); h1/h2/title = `round(0.8 × range.min)`. A size is accepted when (1) the slot fits its archetype box, the content box and avoids keep-outs, (2) line count ≤ `data-max-lines` (hero 3, h1 3, title 3, body 6, other 2), (3) no lone last word (the last of ≥ 2 lines has ≥ 2 words or at least 35 % of the widest line's width), (4) lines are balanced (`text-wrap: balance` where available; else widest − narrowest non-last line ≤ 30 % of the slot width, otherwise a `warnings` entry). Status: `fit` = accepted at ≥ the range minimum; `shrunk` = accepted below it; `floor` = accepted only at the floor; `overflow` = nothing accepted (size left at the floor; QA D2/D3 report it). `fitSlide` never throws for overflow.

Requirements:
- **PNG/JPEG output** is exactly 1080×1440 (PNG) or 1080×1350 (JPEG, `crop:"4x5"` = rect `{0,45,1080,1350}`), sRGB, **no alpha** (opaque background filled first; canvas context `{alpha:false, colorSpace:"srgb"}`), painted at `paintScale` 2 then `downscale`d.
- **svg painter** (reference for Blink/Gecko): serialises the slide with `XMLSerializer` into `<svg><foreignObject><div xmlns="http://www.w3.org/1999/xhtml">`, inlines computed custom properties as an inline `style`, embeds `fontCss()` and converts every `<img>`, `background-image: url(...)` and `blob:` URL into a `data:` URI, loads it as an `Image`, draws it.
- **replay painter** (WebKit/iOS, where `foreignObject` taints the canvas): walks the DOM in paint order and redraws from `getBoundingClientRect()` / computed style: solid and linear-gradient backgrounds, borders and radii, simple shadows, images, inline `<svg>` (each serialised and drawn as an image), 2D transforms, clip-path `inset()`, text via `ctx.fillText` **per `.w` word box** with `ctx.direction`, `ctx.font` from computed style, `textAlign` start/end, no letter-spacing; elements with `opacity < 1` (group opacity) are drawn to an offscreen canvas and composited once. Unsupported computed styles (filter, mask, mix-blend-mode, backdrop-filter, writing-mode) make `supports()` return `ok:false` and `toCanvas` throw `E_PAINT_UNSUPPORTED`.
- Parity: for the 20 types × 6 presets the two painters must reach **SSIM ≥ 0.98** (`tests/parity/`), and each painter must reach **≥ 0.995** against the committed golden (`tests/golden/`).

```ts
  };
};
```

```ts
interface Kit { files: ExportFile[]; zip: ExportFile | null; report: QAReport; skipped: Array<{ path: string; reason: string }> }
interface SaveResult { mode: "downloads" | "share" | "anchor"; saved: string[]; declined: string[]; failed: Array<{ name: string; error: string }> }
```
Requirements:
- **Everything is derived from the spec**: the exporter calls `CS.core.render.deck(spec, brand, { mode:"export", useFrozen:true })` itself, so exports do not depend on the Studio's on-screen DOM.
- **PNG** `3x4/NN.png` 1080×1440; **JPEG** `4x5/NN.jpg` 1080×1350 (`y 45–1395`), q 0.92, ≤ 8,000,000 bytes (lower the quality in 0.02 steps to fit); strip all metadata (canvas encoders add none).
- **MP4 cover** (`3x4/01-cover.mp4`, 1080×1440; `4x5/01-cover.mp4` = same frames cropped to 1080×1350): H.264 High at level 4.0 (`avc1.640028`), **yuv420p, limited (TV) range, BT.709 primaries, transfer and matrix** like the HyperFrames lane, 30 fps constant, `seconds` from `spec.cover.motion.seconds` (default 6) ⇒ `frames = round(seconds × 30)`, no audio, fast-start (`moov` before `mdat`), keyframe at frame 0 and at least every 30 frames, bitrate 8 Mbit/s. Frame `i` is `hf.seek(i / 30)` → `paint.toCanvas(slide1, { scale: 1 })`. **Colour is explicit, not left to the browser:** each frame is converted by the exporter itself (sRGB canvas pixels → I420, BT.709 matrix, limited range, 2×2 box chroma) and handed to the encoder as a `VideoFrame` with `colorSpace` bt709/bt709/bt709, `fullRange: false`, because browsers differ in the matrix, range and transfer they choose for a canvas frame (full-range `yuvj420p`, BT.601 and an "sRGB" transfer tag were all seen). Blocks that did not change since the previous frame are not converted again. Whatever the encoder then writes, `normalise` rewrites its header: `level_idc` is lowered to 40 when the stream fits level 4.0 (hardware encoders write 5.0; the check covers frame size, macroblock rate, DPB and bit rate) and the SPS VUI and the container `colr` box say BT.709, limited range. If `mp4.support()` is false the kit omits the video and lists `{path:"3x4/01-cover.mp4", reason:"no H.264 encoder"}` in `skipped`; `posting-guide.md` then contains the «صدّر الفيديو من الكمبيوتر» note.
- **PDF** one page per slide, MediaBox `[0 0 1080 1440]`, each page one JPEG (q 0.92) full-bleed (`/DCTDecode`), document `/Title` from `opts.title`, no author/producer strings that name a person (producer `Carousel Studio`).
- **Kit layout** (`CS.export.kitFiles(spec)`; ZIP entries are rooted at `carousel-kit/`; ZIP name `<spec.id>-kit.zip`). The default kit is made to travel to a phone: **about 3 MB for 8 slides, target ≤ 4 MB** (measured 2.78 MB: PNGs 0.5, JPEGs 0.5, both MP4s 1.2, PDF 0.5):
  ```
  carousel-kit/3x4/01-cover.mp4   3x4/01-cover.png   3x4/02.png … 3x4/NN.png          (format "single": 3x4/post.png)
  carousel-kit/4x5/01-cover.mp4   4x5/01-cover.jpg   4x5/02.jpg … 4x5/NN.jpg          (format "single": 4x5/post.jpg)
  carousel-kit/caption.txt  hashtags.txt  slide-captions.txt  alt-text.txt  posting-guide.md
  carousel-kit/carousel.pdf  qa-report.md  qa-report.json
  ```
  **Source files, opt-in** (`kit(…, { source: true })`, the Export screen's «ملفات المصدر» switch, or the single export `source`, a `<spec.id>-source.zip` rooted at `carousel-source/`; Claude Code: `--formats …,source`): `spec.json`, `cover.hf.html` (carousels with motion; it opens with a licence header: Apache-2.0, the HyperFrames format, the embedded OFL fonts by name) and `studio-source.html`. They add over 10 MB, nearly all embedded fonts, and are built only on request (the composition is not even generated for the default kit). They sit between `carousel.pdf` and the QA report in the kit order.

  `NN` is the zero-padded 2-digit slide position; labels inside `slide-captions.txt` and `alt-text.txt` are `NN: text` lines with Western digits (technical labels). `studio-source.html` is `ctx.sourceHtml()` — the Studio serialised **credit-free** (`CS.ui.serializeSource()`), so X1 can scan every kit file.
- **Save order** (`mode:"auto"`): Web Share with files when `navigator.canShare({files})` and the call comes from a user gesture on a touch device → `claude.use("downloads").save({filename, data})` per file (a single ZIP when more than 3 files) → `<a download>` fallback. `declined` is not an error. `extension_not_enabled` ⇒ files one by one.
- **Dependencies** load lazily: `import(CS.export.DEPS.mediabunny.url)` only when an MP4 is requested. `fflate` is optional (the ZIP writer is built in); if a builder uses it, it must be loaded from `DEPS.fflate.url` and fall back to the built-in writer when the load fails. No other network request is ever made.
- **Automation** (Claude Code lane): `CS.automation = { ready: Promise<void>; setSpec(spec): Promise<void>; runQa(): Promise<QAReport>; exportAll(opts?): Promise<{ ok: boolean; files: Array<{ path: string; bytes: number; mime: string }>; report: QAReport }>; readChunk(path: string, offset: number, length: number): Promise<string /* base64 */> }`. `exportAll` keeps the bytes in memory (`window.__csFiles: Map<path, Uint8Array>`); `render.mjs` pulls them with `readChunk` in 4 MiB slices.

### 5.1 The slide DOM (what `CS.core.compose.slide` returns)

Rules:
- **Fixed class vocabulary** (B6 and B3 may rely on these and on nothing else): `cs-slide cs-bg cs-decor cs-header cs-footer cs-content cs-a-<type> cs-slot cs-handle cs-meta cs-counter cs-swipe cs-savepill cs-kicker cs-headline cs-sub cs-title cs-body cs-bullets cs-bullet cs-sides cs-side cs-side-label cs-side-text cs-number cs-num cs-unit cs-ord cs-attribution cs-bridge cs-cta cs-cta-text cs-cta-icon cs-media-slot cs-ltr cs-rtl cs-emoji cs-em cs-ln w`. Presets never add classes; they add `data-*`-scoped CSS rules and may place pseudo-elements.
- `dir`/`lang` on `.cs-slide`: `rtl`/`ar` for Arabic dialects, `ltr`/`en` for `en`. All layout uses **logical properties** (`margin-inline-start`, `inset-inline-end`, `text-align: start`) so the same CSS mirrors.
- Footer slot order in the DOM is `savepill, counter, swipe`. For `data-swipe="arrow-ltr"` (English-UI audience) archetype CSS reverses the footer (`flex-direction: row-reverse`) so the cue sits on the edge it points to; for `neutral` the `.cs-swipe` element is omitted and the counter carries progress; the neutral cue is the counter, and from 1.1 a quiet progress rail inside the counter slot (`style.rail`). On the last slide there is no swipe cue (`data-last="1"`); when the cue shows a word (an arrow cue) it becomes «باقي {k}» on the last two slides. Version 1.0 also drew two empty cards on the slide edges for this cue; they carried nothing from the neighbouring slide and were removed in 1.1.0 (the rail is the neutral cue's content).
- The slide root is exactly 1080×1440 CSS px (1080×1350 for the `ig-4x5` canvas). Nothing inside may use viewport units.
- `aria-hidden="true"` on bg/decor. Words are `<span class="w" data-w="i">`; physical lines (after fit/freeze) are `<span class="cs-ln" data-m="ln" data-m-i="j">` blocks containing `.w` children. Compose also sets `data-m-slot="<slot>"` on every `.w` and `.cs-ln`.
- **Chrome content.** Header start: the brand logo (`"logo"` asset, 56 px high, never mirrored) when the brand has one and `preset.chrome.handle.logo` is `auto`, followed by the handle `brand.handle` as an LTR run; header end: `spec.style.metaLabel` (slot omitted when empty). Footer: save-pill text, step labels, myth/fact/versus labels and the swipe label come from `locale-defaults.json → slideStrings` / `swipeCue.labels` for `spec.locale.dialect` (engine strings follow the post's dialect, never the Studio UI dialect); the counter uses `counter.formats`.
- Emphasis: `<mark class="cs-em" data-m="em">` around whole `.w` units. Kashida: the chosen word contains U+0640 characters and carries `class="w cs-kashida"`.

### 5.2 Partial format (`templates/archetypes.html`)
One `<style id="cs-archetype-css">` (layout only) followed by one `<template>` per type:
```html
<template data-archetype="item" data-version="1" data-default-variant="base"
          data-variants="base ghost-number side-number media" data-chrome="handle meta counter swipe">
  <main class="cs-content cs-a-item" data-layer="content">
    <div class="cs-slot cs-ord"    data-slot="ord"    data-field="ord"    data-kind="ord"  data-role="small" data-optional></div>
    <h2  class="cs-slot cs-title"  data-slot="title"  data-field="title"  data-kind="text" data-role="title" data-max-lines="3" data-edit="text"></h2>
    <p   class="cs-slot cs-body"   data-slot="body"   data-field="body"   data-kind="text" data-role="body"  data-max-lines="6" data-edit="text"></p>
    <div class="cs-slot cs-media-slot" data-slot="media" data-field="media" data-kind="media" data-optional></div>
    <p   class="cs-slot cs-bridge" data-slot="bridge" data-field="bridge" data-kind="text" data-role="small" data-max-lines="2" data-optional data-edit="text"></p>
  </main>
</template>
```
Attribute grammar on a slot element:
| Attribute | Values | Meaning |
|---|---|---|
| `data-slot` | name (unique within the slide) | key part: `s03.title` |
| `data-field` | Slide property: `kicker headline sub title body bullets sides number ord attribution bridge cta media` | what feeds the slot |
| `data-kind` | `text list sides number ord media cta` | how the engine fills it (see below) |
| `data-role` | `hero h1 h2 title body small micro number` | typographic role ⇒ font-size tokens and fit range |
| `data-optional` | boolean | slot is omitted (no empty box) when the field is empty; absent ⇒ rendered empty (editable placeholder in `edit` mode) |
| `data-max-lines` | integer | fit line limit |
| `data-edit` | `text` or absent | whether the Studio makes it `contenteditable` |

`data-kind` fill rules: **text** → `CS.core.text.toHTML(value)` inside the element; **list** (`bullets`) → `<li class="cs-bullet" data-m="bullet" data-m-i="0">` per entry (container is `<ul class="cs-bullets">`); **sides** (`compare`, `myth-fact`) → two `<div class="cs-side" data-side="0|1" data-m="side"><span class="cs-side-label">…</span><p class="cs-side-text">…</p></div>`; **number** → `<bdi dir="ltr" class="cs-ltr cs-num" data-m="num" data-run="number" data-value="413" data-decimals="0">413</bdi><span class="cs-unit" data-m="unit">%</span>`; **ord** → the ordinal formatted in `locale.digits` (`01` style is a preset look, the text is `1`; the label «الخطوة {i} من {n}» comes from `locale-defaults.json → slideStrings.stepLabel`), **media** → `<img>`/`<svg>`/`<video>` for the `media.slot` kind (`icon` inline SVG, `photo` `cutout` `screenshot` `ui` `<img>`, `plate` `<video muted playsinline>` or `<img>`), `object-fit` per slot kind, `calmZone` copied to `data-calm`; **cta** → `<span class="cs-cta-text">…</span><span class="cs-cta-icon" aria-hidden="true"></span>`.

Archetype CSS (layout) may use `display:flex|grid`, `gap`, logical properties, `position:absolute` inside `.cs-slide`, `aspect-ratio`, `object-fit`, `text-wrap: balance`, `min-/max-` sizes, custom properties from 6.2. It must stay inside the **paintable subset** (6.3) and may not set any colour, font family, weight, border radius or shadow (those are presets').

### 5.4 Which slots are fit
Every `data-kind="text"` slot, every `bullets` item, every `sides` text, `number` and `ord` are fit slots with a key (`s03.title`, `s03.bullets.2`, `s03.sides.1`, `s03.number`). Chrome (`handle`, `meta`, `counter`, `swipe`, `savepill`) is never fitted and uses `--cs-fs-micro`. Placeholders for empty editable slots are added by the Studio only (`data-placeholder` + CSS `:empty::before` in `studio.css`), never by the engine, so exports are clean.

### 5.5 Motion data attributes
Motion touches the DOM **only** through these hooks (set by `CS.core.compose`; B3 may add `data-m-*` attributes at `build` time, never classes):
| Attribute | On | Values | Meaning |
|---|---|---|---|
| `data-m` | any animatable element | `bg decor decor-item chrome footer handle meta counter swipe savepill kicker headline sub title body bullets bullet sides side number num unit ord media bridge cta em ln stroke` | role name used by track selectors (words are selected by the class `.w`) |
| `data-m-i` | `.cs-ln`, `bullet`, `side`, `decor-item` | integer ≥ 0 | index within its slot (stagger order); words use `data-w` |
| `data-m-slot` | `.w`, `.cs-ln` | slot name (`headline`, `title`, `body` …) | select the words of one slot: `.w[data-m-slot="headline"]` |
| `data-value`, `data-decimals` | `.cs-num` | Western number string, integer | counter target; the engine keeps the final text in the element |
| `data-m-group` | wrappers | `opacity` | the only elements that may carry `opacity` mid-animation (always whole words, lines, slots or decor) |
| `pathLength="1"` | SVG `<path data-m="stroke">` | – | lets `dash` run 0→1 |

Animatable properties (whitelist, supported identically by WAAPI and the replay painter): `opacity`, `transform` (translate, scale, rotate), `clip-path: inset()`, SVG `stroke-dashoffset`. **Not allowed:** `filter`, `backdrop-filter`, blend modes, masks, `letter-spacing`, `font-size`/`font-variation-settings` animation, per-letter splitting, any change to `direction`.

### 5.6 Timeline data format (`Timeline`, JSON-serialisable)
```ts
interface Timeline {
  v: 1; recipe: string; feel: "calm" | "story"; seed: number;
  duration: number; fps: 30; frames: number;                      // frames = round(duration × fps)
  times: { holdIn: number; resetEnd: number; settleBy: number };  // defaults 0.4 · 0.75 · 5.6 (platform.plugin.motion)
  tracks: Track[]; counters: CounterTrack[];
  contentClip?: { x: number; y: number; w: number; h: number };  // zoom only: fixed slide-space aperture around the moving content
}
interface Track {
  id: string; sel: string;                       // scoped to the slide root; may use only [data-m=…], [data-m-slot=…], [data-m-i=…], [data-w=…], .w, .cs-ln
  from: Props; to?: Props;                       // `to` defaults to the element's resting (poster) state
  t0: number; t1: number;                        // build window in seconds, resetEnd ≤ t0 < t1 ≤ settleBy (after stagger)
  ease: EaseName; origin?: "center" | "start" | "end" | "top" | "bottom" | "start-bottom";   // transform-origin, logical
  stagger?: { each: number; from?: "start" | "end" | "center" | "random"; seed?: number };
  reset?: { to?: Props; ease?: EaseName };      // break-apart target; if reset.to differs from `from`, reset.to.opacity must be 0 (the jump is invisible)
}
interface CounterTrack { id: string; sel: string; from: number; to: number; t0: number; t1: number; ease: EaseName; decimals: number }
interface Props { opacity?: number; x?: number; y?: number; scale?: number; scaleX?: number; scaleY?: number; rotate?: number; clipInset?: [number, number, number, number] /* % top,right,bottom,left; logical start = right in RTL */; dash?: number /* 0..1 */ }
type EaseName = "linear"|"in-quad"|"out-quad"|"in-out-quad"|"in-cubic"|"out-cubic"|"in-out-cubic"|"out-quint"|"out-expo"|"in-out-expo"|"out-back";   // out-back overshoot ≤ 6 %
```
**Poster-first state function** (normative; `seek(t)` is a pure function of `(timeline, t)`): for one element with build window `[a, b] = [t0 + delay, t1 + delay]` (delay = stagger offset):
- `t ≤ holdIn` or `t ≥ settleBy`: **rest** (the finished poster).
- `holdIn < t < resetEnd`: interpolate rest → `reset.to ?? from` with `reset.ease ?? "in-cubic"` (all elements together; the poster breaks apart in ≤ 0.35 s).
- `resetEnd ≤ t < a`: hold `from`.
- `a ≤ t ≤ b`: interpolate `from → to` with `ease`.
- `b < t < settleBy`: rest.
Counters interpolate `from → to` over `[t0, t1]` and write the formatted text (`locale.digits`); at `t ≤ holdIn` and `t ≥ settleBy` the text equals the poster text. Frame `0` and frame `frames − 1` are both **rest** ⇒ the loop is seamless. Gate V1 verifies it with two bars: the **loop bar** (SSIM ≥ 0.995, PSNR ≥ 45 dB) for the lossless comparisons, the last frame against frame 0 of the same encode and, in the Studio, the painted frame 0 against the poster; and the **poster floor** (SSIM ≥ 0.99, PSNR ≥ 32 dB, `plugin.motion.posterSsimMin` / `posterPsnrMinDb`) for frame 0 of the *encoded* MP4 against the lossless poster PNG, because 4:2:0 H.264 loses colour detail on thin red-on-white edges and can never reach 45 dB against a PNG (about 33 dB on the shipped example; `check_video.mjs` applies it).

Arabic motion rules: animate by **word (`.w`) or line (`.cs-ln`)** only, never by letter; opacity only on `data-m-group="opacity"` elements; layout never changes during motion (counters reserve their final width via `min-inline-size`); transforms use logical axes (the recipe converts "start" to ±x according to `dir`); frame 0 equals the exported PNG of slide 1.

`recommend(spec)` and Python `pick_motion` use first match: urgency (2+) ⇒ `drop-clock`; spread (2+) ⇒ `map-dots`; myth-fact / P4 / decision (2+) ⇒ `stamp`; mistakes ⇒ heartbeat `story`; cover change marker ⇒ `split`; cover numeral (except years) or stat/number slide ⇒ `counter`; steps / framework / how-to ⇒ `reorder`; news naming a Latin product or a direct reader question ⇒ `notify`; launch words ⇒ `curtain`; news / story / case-study ⇒ `story`; one or two marked words ⇒ `zoom`; otherwise `highlight-sweep`. Ordinary conjunctions such as «ولا» never tag a change. The Python picker can avoid the newest earlier sibling post's recipe: next matching allowed rule, else first different allowed recipe, with a note naming the previous recipe. An unknown or unshipped id falls back to `calm` with a NOTE. `prefers-reduced-motion` affects only live preview (opacity-only timeline); exports are always full.

`contentClip` creates a temporary full-slide wrapper with a fixed inset clip around the content layer, active only during motion. Its containing block and stacking level match the original content layer, so the measured center transform origin stays correct and preset backgrounds cannot hide the camera. It is removed on destroy; header/footer are outside it. This keeps the camera safe during reset too, when an interpolated clip on the scaled layer would leak. New overlay definitions carry an optional numeric `z`, measured relative to the content's own stacking level, so below/above content works on every preset without changing existing overlay stacking.

External motion (Q19, v1): when `cover.motion.source = "external"` the cover has a text-free background plate (`media.slot = "plate"`, a `<video>` whose first frame equals its last frame, or a looping ping-pong). The type layer builds on top with `calm`; the loop gate V1 still applies. In the Claude Code lane the plate is a `<video>` clip in the composition; in the Studio `CS.export.cover` decodes it frame-exactly with `VideoDecoder` under the DOM. **If that path is not ready at integration, external plates ship in the Claude Code lane first and the Studio shows «الحركة الخارجية متاحة في Claude Code».**

### 6.3 `decor.css` rules (checked by `preset_lint.py`)
- Every selector starts with `.cs-slide[data-preset="<id>"]` (variants add `[data-type="…"][data-variant="…"]`); only the class/attribute vocabulary of 5.1/5.5 may appear.
- **Allowed properties:** colours from `var(--cs-*)`, `background` (solid, `linear-gradient`, `data:` images), `border*`, `border-radius`, `box-shadow` (≤ 2 simple layers, no spread-only tricks), `outline`, `padding/margin` (logical), `width/height/min/max`, `transform` (2D), `clip-path: inset()`, `text-decoration` (underline, thickness, offset), `text-decoration-color`, `font-weight` (within the loaded range), `text-transform: none`, `content` (for decorative pseudo-elements: ornaments, quotes, ruled lines; never real copy), `display`, `position`, `inset-*`, `z-index`, `opacity` **only** on `.cs-decor` and its descendants and on `.cs-bg`.
- **Forbidden:** `filter`, `backdrop-filter`, `mix-blend-mode`, `background-blend-mode`, `mask*`, `writing-mode`, `letter-spacing` ≠ 0, `word-spacing`, `text-align: justify`, `text-justify`, `font-style: italic|oblique`, `font-synthesis*`, `font-family` (fonts come from tokens), `font-size` on text slots (sizes come from fit), `animation*`, `transition*`, `@keyframes`, `@import`, `@font-face`, `@media`, `@supports`, `!important`, viewport units, `position: fixed`, `url()` that is not `data:`, `:hover`/`:focus`/`:active`, `opacity` or `rgba()/hsla()` text colour on any text-bearing selector.
- Colour literals are not allowed except inside `data:image/svg+xml` URLs, where the placeholders `{{bg}} {{surface}} {{ink}} {{inkMuted}} {{accent}} {{accent2}}` are substituted by the registry with the resolved colour, percent-encoded (`%23E3262B`), per slide.
- Size: `decor.css` ≤ 64 KiB. Kashida: only if `decor.kashida.allowed`; the engine never adds U+0640 otherwise.

### 6.4 Resolve order (normative for `CS.core.resolve`)
1. Clone `preset.json`. 2. **Brand:** for each role in `brandBindings` that the brand palette defines, replace the role; if `"fonts"` is bound and the brand names a font that exists in the registry, replace `type.display/heading` families by `visual.fonts.display`, `type.body` by `visual.fonts.body`, `type.latin` by `visual.fonts.latin` (weights stay). Brand `visual.locks` (token paths) are recorded as locked. 3. **Occasion:** if `spec.style.occasionId` resolves to a pack whose `presetsAllowed` is empty or contains the preset, apply `overlay.tokens` for keys in `overlay.allowedKeys` ∩ `{roles.accent2, background.texture, decor.motif}` that are not locked; it can never touch the logo, primary font, handle or a locked key. 4. **Post overrides** (`spec.style.overrides`) and 5. **slide overrides** (`slide.overrides`, then `slide.variant`): dotted paths from this closed set — `roles.{bg,surface,ink,inkMuted,accent,accent2}`, `type.{display,heading,body}.{family,wght,lh}`, `type.latin.{family,wght}`, `type.scale.{hero,heroTarget,h1,h2,title,body,small,micro}`, `layout.{align,coverAnchor,headlineWidth}`, `decor.{highlight,numbering,texture,motif}`, `background.kind`, `chrome.counter.format`, `chrome.swipe.style`. Locked or unknown paths are ignored and logged. 6. **Floors last:** sizes never go below `floors`; text pairs `ink/bg`, `ink/surface`, `inkMuted/bg` must reach `contrastBody`, `accent` used as text (`decor.highlight = "color"`) `contrastLarge`/`contrastBody` by size, `onAccent/accent` `contrastBody`; a failing foreground is moved with `color.ensureContrast` (OKLCH lightness only, hue kept) and the change is logged in `adjustments` with a bilingual reason for «ليه اللون ده؟». 7. ## 7. Quality gates

Rules are **data**. `data/qa-rules.json` (B4) holds the gate registry; the word lists, orthography rules and dialect markers it points to live in `data/rules/copy.json` (B7), `data/rules/ortho.json` (B8) and `data/dialects/*.json` (B8). The Python engines (`_cs.qa`, `_cs.lint`) and the JavaScript engine (`CS.qa`) read the same files and must give the same verdicts on `tests/conformance/corpus/`.

### 7.1 Severities, status, exit codes
- **BLOCK** disables «حزمة النشر» until fixed (the Check screen offers «صلّح تلقائياً» first). **FIX** exports with a badge. **NOTE** is advice.
- Only gates marked *overridable* accept «صدّر رغم ذلك» (recorded as `overridden:{reason,at}` in `spec.qa.results` and in `qa-report`). Technical gates (D*, V1, X1, A1, N1, B1-rendered) are **never** overridable and must produce **zero false BLOCKs on `tests/corpus-clean/`**. The overridable set is exactly: `C1.*`, `C2.body-hard`, the length checks on the creator's own words (`C2.title-words`, `C2.body-words`, `C2.bullets`, `C2.dense-words`, `C2.slide-words`, `C2.cta-words`, `C2.share-words`: a creator who keeps a long line keeps it, recorded as «تجاوز»), `C3.*`, `O1.*`.
- `status`: `block` if any non-overridden BLOCK; else `fix` if any non-overridden FIX; else `pass`. CLI exit code: `pass`/`NOTE`-only → 0, `fix` → 1, `block` → 2.
- Checks flagged `"engines":["model"]` (meaning word first, gap not answered on the cover, voice, dialect purity beyond deny markers, text inside AI images, sensitivities needing judgement) are **never emitted by code**; the `cs-arabic-editor` / `cs-art-director` agents (or the inline role pass) run them from the same descriptions, and `references/qa-gates.md` (B9) lists them.

Field semantics:
- `scope` ∈ `text | rendered | export | after-generation | text+rendered | text+model`. `engines` ⊆ `py js model`. A check may narrow its gate's `engines`.
- `appliesTo.slideTypes` (omit = all), `formats` (omit = all), `dialects` (omit = all), `modes` (`guided`, `fast`).
- `params`: literal values or `{"$platform": "dot.path"}` (resolved at load; array indexes as `.0`; an unknown path is a load error). Checks read thresholds only from `params`.
- `autofix`: `null` or `{ "kind": "digits|punct|spacing|bind|tatweel|ellipsis|refit|split|scrim|oklch", "engines": ["py","js"] }`. Only deterministic, high-precision fixes carry an `autofix`.
- `msg` / `fix` are templates; every finding supplies `{count}` `{max}` `{min}` `{n}` `{text}` (≤ 40-character snippet) plus check-specific variables documented in the check's `vars` array.
- A finding becomes `{ gate, rule: <check id>, sev, slide?, el?, msg, fix, autofixed:false }` (the shape of `qaResult` in the schemas).

### 7.4 Rule data files (formats shared by B4, B7, B8, B10)
**Entry** (used by `copy.json` lists and by `dialects/*.json` `deny`/`warn`):
```ts
interface Entry { id: string; text?: string; pattern?: string; match: "word" | "phrase" | "regex"; flags?: "u" | "ui"; clitics?: boolean; dialects?: string[] /* default ["*"] */; sev?: Severity; note?: Msg; suggest?: string; value?: number }
```
Matching (normative, both engines): run on the NFC text with U+064B–065F, U+0670 and U+0640 removed (offsets map back to the original). `word` = a whole token of kind `ar` or `latin` equal to `text` (Latin case-insensitive); with `clitics:true` the token may carry one proclitic from `ortho.json → clitics` before it. `phrase` = a run of words equal to the entry's words, separated by any whitespace, same boundaries. `regex` = `pattern` in the portable subset (3.1); "boundaries" are written with explicit classes, e.g. `(^|[^\u0621-\u064A])…($|[^\u0621-\u064A])`.

**`copy.json`** (B7): `{"schemaVersion":1,"dataVersion":"1.0.0","lists":{ "<name>": {"description":"…","entries":[Entry]} }}` with lists `aiWords stockOpeners hypeWords abstractWords fearWords conspiracy overclaim commentBait introPhrases stiffMsa translationese bindLabels numberWords` (each list may carry `en` entries; `numberWords` entries have `value`). Hype seeds: «الحقيقة الصادمة»، «سر خطير». Each list is also keyed by language through `dialects` (`["en"]` for English entries).

**`ortho.json`** (B8): `{"schemaVersion":1,"dataVersion":"1.0.0","clitics":["و","ف","ب","ل","ك","ال","وال","بال","كال","فال","لل","ولل"],"rules":[Rule]}` with
```ts
interface Rule { id: string /* ORTHO-<AREA>-<NNN> */; kind: "word-map" | "char" | "regex" | "check"; sev: Severity; confidence: number /* 0-1 */; autofix: boolean; dialects?: string[]; msg: Msg;
                 map?: Record<string, string> /* word-map: key → replacement (clitics honoured); char: char → char */; clitics?: boolean; pattern?: string; replace?: string; check?: CheckName }
type CheckName = "mixed-digits" | "persian-digits" | "persian-letters" | "space-before-punct" | "missing-space-after-punct" | "latin-punct-in-arabic" | "digit-glued-to-word" | "double-space" | "programmatic-tatweel" | "ellipsis-dots" | "repeated-punct" | "percent-sign" | "lam-latin-stranded" | "number-noun-unbound" | "emoji-edge";
```
`autofix:true` is allowed only for: Persian letters/digits, space before ، ؛ ؟, Latin punctuation inside Arabic, digits glued to words, mixed digits, programmatic tatweel, double spaces, ellipsis dots, repeated punctuation, lam-latin attach, number-noun binding. Hamza (انشاء→إنشاء، الوان→ألوان، إنشاء الله→إن شاء الله), ة/ه and ى/ي lists, shadda, translationese and transliterated English are suggestions with `confidence`.

Built-in check semantics (both engines): `mixed-digits` (more than one digit system outside excluded tokens), `persian-digits` (U+06F0–06F9), `persian-letters` (ی U+06CC, ک U+06A9, ھ U+06BE → ي ك ه), `space-before-punct` (whitespace before `، ؛ ؟ : ! . , ; ?` that follows Arabic text), `missing-space-after-punct` (`، ؛ ؟` directly followed by a letter), `latin-punct-in-arabic` (`, ; ?` between Arabic-script letters/spaces), `digit-glued-to-word` (Western digits touching Arabic letters, except a proclitic form like «بـ5»), `double-space`, `programmatic-tatweel` (U+0640 outside the slide's `kashidaWord`, or runs of ≥ 3 in body text), `ellipsis-dots` (`...`, `. . .` → `…`), `repeated-punct` (`؟؟ !! ،،`), `percent-sign` (mismatch with the digit system), `lam-latin-stranded` (`لـ/بـ/الـ/وبـ` + whitespace + Latin/number), `number-noun-unbound` (number + ordinary space + Arabic noun), `emoji-edge` (emoji first/last on an Arabic line → NOTE).

**`dialects/<code>.json`** (B8): `{"schemaVersion":1,"dataVersion":"1.0.0","dialect":"eg","label":Msg,"markers":["مش","ده","إزاي",…],"deny":[Entry],"warn":[Entry],"lexicon":{"not":["مش"],"will":["هـ"],"want":["عايز"],"think-that":[…],"thing":[…],"how":[…],"why":[…],"now":[…],"a-lot":[…],"do":[…],"before":[…],"free":[…],"this":[…]},"cta":{"save":["احفظ …"],"send":[…],"question":[…],"keyword-dm":[…],"follow":[…]},"registerNotes":Msg}`. `deny` entries fail a post in this dialect (e.g. «مو» in `eg`, «عايز/إزاي/دلوقتي» in `gulf`); `lexicon` is the swap table of draft 05 §3.3 (B10 renders hook skeletons from it). `en.json` has empty `deny`/`warn` Arabic lists and English cliché lists.

| `exported` | + export scope: D1, V1, X1 on the produced files |

### 7.6 Reports
- `qa-report.json` = `qa-report.schema.json`; `qa-report.md` = `CS.qa.report.toMarkdown(report, lang)`: title + status line; a table of counts; sections BLOCK / FIX / NOTE with one bullet per finding (`s03 · C2.body-words · message — fix`); an «تجاوزات» (overrides) list with reasons; environment (painter, dialect, digits, fonts). Never contains the owner's name.
- `_cs.report.to_markdown` and `CS.qa.report.toMarkdown` produce **byte-identical** output for the same report (conformance test).

### 8.5 Handoff (Claude → Studio)
1. The skill writes `spec.json`, runs `validate.py spec spec.json --checkpoint script --lint` (0/1 continue, 2 fix first).
2. `build_studio.py --spec spec.json --brand brand.json --view script --out studio.html`.
3. Claude publishes the file with the Artifact tool (Claude Code: from disk; chat/Cowork: from the sandbox file), declaring the capabilities the page uses (`downloads`, `assets`, `sample`, `user`, page self-publishing — exact names verified in M0 and held in `CS.ui.CAPABILITY_NAMES`), and gives the user the link.
4. Claude records the returned URL in its working copy (`spec.meta.studioUrl`, plan slot `studioUrl`). The page does **not** need its own URL (it reads `location.href`).
5. Guided mode: user reviews the **Script view** (Arabic is reviewed here, never as chat text) → «تمام، صمّم» → the page sets `checkpoint:"design"` and `approvals.script`; fast mode opens in **Design view**.

### 8.6 Edits coming back
- **A. Studio save (preferred).** «حفظ» → `CS.core.spec.bump(spec,"studio")` (rev+1), serialise the running page with the new `cs-spec` block (`CS.ui.serializeForPublish(spec)`; unsaved editor state excluded, stashed in `sessionStorage`), publish to the same URL through the self-publish capability. On a version conflict show «Claude عدّل البوست — نرجّع تعديلاتك؟» and re-apply the user's patch on the newer `rev`.
- **B. Claude-side edit.** Claude reads the artifact (Artifact tool, `read`), `extract_spec.py page.html -o spec.json --expect-rev <rev>` (exit 75 on mismatch ⇒ re-read), edits `spec.json`, re-validates, `build_studio.py`, republishes to the **same URL** with the same file path. A publish refused for conflict hands back the live version: re-run extract, merge, publish again — never overwrite.
- **C. JSON-patch fallback** (when page-side publishing is unavailable): «انسخ التعديلات» copies a `CS.core.patch.envelope` (`{"carouselStudioPatch":1,"specId","baseRev","patch":[{"op":"test","path":"/rev","value":N}, …]}`) which the user pastes in chat; Claude applies it with `extract_spec.py --apply-patch` against its own `spec.json` (exit 75 if `baseRev` ≠ current `rev`).
- `rev` increments on **every** write by any party; `meta.updatedBy` records who.

### 8.7 Brand Home
Same runtime (`CS.ui.mountBrandHome`, `CS.ui.brandBook.mount`). Tabs: Brand Book, Plan, Ideas, Posts (links to Post Studios). It embeds the canonical `brand.json`; approving the Brand Book stamps `version` and `approvedAt`. Logo, photos and owned fonts are kept in the `assets` capability; the ≤ 60 KB logo data URI in `brand.visual.logo.dataUri` makes every spec self-sufficient. The Brand Book PDF and “copy brand card” (the capsule) are credit-free.

### 8.8 Privacy
Nothing leaves the page except what the user triggers: file downloads, Web Share, and (Studio owner only) `sample` calls to Claude. No analytics, no beacons, no third-party requests except `cdn.jsdelivr.net/npm/mediabunny@1.61.0` when an MP4 is exported. Brand data stays in the user's artifact/workspace.

## 9. Script CLIs

### 9.1 Conventions (every script)
- Run as `python <skill>/scripts/<name>.py …` (Python 3.11, stdlib only) or `node <skill>/scripts/<name>.mjs …` (Node ≥ 22). At the top of every Python script: `sys.path.insert(0, str(Path(__file__).resolve().parent))` then `from _cs import paths; paths.ensure_utf8_stdio()`.
- Options are `--long value`; booleans are bare flags; `-` means stdin/stdout; every script supports `--help` (exit 0) and `--format text|json` (default `text`; `json` prints one JSON document to stdout). Human text is Arabic-first where it addresses the user, English for technical errors.
- Read files as UTF-8, write UTF-8 with LF and a trailing newline; write atomically (temp file + `os.replace`). Never print secrets; never make network calls.
- Exit codes: table in 0.4. `QAResult[]`/`QAReport` shapes: schemas.
- Scripts never prompt interactively.

### 9.2 Plugin scripts
