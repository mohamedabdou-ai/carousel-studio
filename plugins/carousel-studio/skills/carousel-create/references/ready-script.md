# The creator's own script

Use this when the user pastes a finished script: numbered slides (①, «1.», «Slide 1», «سلايد 1») or sections split by `---`, or says «ده السكريبت» / «السكريبت جاهز». Their words are the script. This lane skips the writers' room: **do not read** `rounds.md`, `flow.md`, `architectures.md`, the team charter, the Creative Director manual, the hook files, the schemas or any script's source, and do not dispatch the strategist, copywriter, panel, motion designer or Creative Director. Read this page and its brand lookup and, if you are unsure of a word, the post's `dialects/<code>.md`.

## Steps
1. **Brand.** Find `brand.json` (`brand-lookup.md`, "Where to look"). Take the dialect and digits from it; ask nothing else.
2. **Save the script** exactly as pasted to `<post>/script.md` (the post folder is `post-YYYYMMDD-NNNN` in the workspace or next to the brand).
3. **Structure:** `python scripts/script_to_spec.py --script <post>/script.md --brand brand.json --out <post> --architecture <one word>`, plus `--style <preset>` when the user named one. When the user says the script is final («كما هو», «زي ما هو», «من غير تغيير», "as is"), add `--no-split2` and keep a long slide 2 with `"keep": ["C3.words"]` in step 5 without asking. The architecture is one of `news, story, case-study, listicle, steps, myth-fact, opinion, comparison, framework, results, offer, lead-magnet`; pick it from the topic in one thought. The script writes `spec.json` and prints what it did (each note is a decision; repeat a note to the user only if it changed their copy) and what is left to fill.
4. **Fill:** write `<post>/fill.json` with only what it asks for, in the post's dialect:
   - `bridges`: one per slide from 2 to the last but one, at most 8 words; it opens the next slide and never repeats its title.
   - `emphasis` (optional): one keyword per slide that is already in its title or headline, e.g. `{"s04": "توقيت"}`.
   - `caption`: `firstLine` (at most 125 characters, a reason to tap «more», not the cover again), `keywordLine` (the words people search for), `body` (the whole caption 300 to 900 characters: the payoff in short lines, no new claims, no numbers that are not in the script), `cta` (the same single action as the last slide), `hashtags` (3 to 5, topic first, no tool or author tags).
   - `perSlide`: one line per slide, at most 100 characters. `alt`: one per slide, in the post's language, saying what the slide says and shows.
   - `edits` only where a note asks for a decision, e.g. two calls to action in one line: keep the one that matches the post (a question for reach, save for a list) as `{"s08": {"cta": {"kind": "question", "text": "…"}}}`.
5. **Check:** `python scripts/script_to_spec.py --spec <post>/spec.json --fill <post>/fill.json --brand brand.json`. A BLOCK is fixed, except one the check marks as the creator's call (a cover over 6 words, say): ask once, in one line. If they keep their words, add `"keep": ["C1.hero-words"]` (the rule the check names) to `fill.json` and run this step again: it records their override («تجاوز»), which the Studio and the export honour. Never search the plugin for how to override. A FIX on the creator's own words is said in one line, never rewritten unless they ask. Then `python ../arabic-proofread/scripts/ortho_lint.py --spec <post>/spec.json --brand brand.json` for an Arabic post; fix spelling it flags in the parts you wrote, and list the ones in the creator's text for them. The `cs-arabic-editor` agent runs only when the user asks for a proofread.
6. **Design:** hand off to carousel-design in the Design view (its "Fast lane"). The cover motion is already set by the Studio's own rule; the Motion tab offers the alternatives, so no motion agent and no storyboard unless the user asks.

## In chat
Three short lines at most before the link: what you kept («سكريبتك زي ما هو»), the one or two decisions (e.g. slide 2 split into two), and the next word to say («تمام، صمّم» or «صدّر»). Never paste the script or the caption back.
